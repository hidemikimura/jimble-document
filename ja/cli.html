    CLI#

    使い方: jimble <コマンド>

  new <name>              プロジェクトの雛形を作る
  migrate                 未適用のマイグレーションを適用する
  codegen <ソースルート>   テーブル定義のコードを生成する（例: src/main/java）
  version                 版を表示する

    jimble new#

    jimble new my-blog

    作られるもの:

    my-blog/
	settings.gradle.kts
	build.gradle.kts
	gradle.properties
	.gitignore
	src/main/java/my_blog/App.java
	src/main/jte/index.jte
	src/main/resources/application.conf
	src/main/resources/migration/my_blog/001_create_note.sql.example
	README.md

    空のディレクトリは作りません。 使う段になってから作ってください。 .example が付いているものは、名前を変えれば有効になります。

    名前の決まり:

    • 使えるのは英小文字・数字・-・_ です
    • 先頭は英字です
    • パッケージ名は - を _ にしたもの（my-blog → my_blog）
    • Java の予約語や、既にあるディレクトリ名は断られます

    理由はエラーメッセージに書いてあります。

    次にすること#

    cd my-blog
gradle wrapper          # Gradle ラッパーを用意する（1回だけ）
./gradlew run           # 起動する
./gradlew jimbleRun     # ホットリロードで起動する

    migrate / codegen#

    ./gradlew migrate
./gradlew codegen

    どちらもアプリの設定（application.conf）とマイグレーションの SQL を クラスパスから探します。プロジェクトの中から Gradle 越しに呼ぶのが確実です。

    io.jimble.db プラグインを入れておくと、compileJava の前に migrate → codegen が自動で繋がります。

    版を確認する#

    jimble version

    jar の Implementation-Version を読んでいます。
